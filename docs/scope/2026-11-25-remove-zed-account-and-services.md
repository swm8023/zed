# 移除 Zed 的 AI、账号与官方服务

## 目标

精简当前 Zed 1.29.3 源码，交付可独立构建和发布的编辑器。保留 Git、本地编辑和开发能力，以及账号无关的扩展和 SSH 远程编辑能力。客户端可以在无法访问 Zed 官方服务的环境中启动和工作。

## 决策基线

### 需求决策

| 范围 | 产品行为 |
| --- | --- |
| AI | 移除 Agent、外部 Agent 和 ACP、内联助手、编辑预测、Copilot、模型与提供商配置、MCP、AI 网页搜索、提示词与 Agent Skills、AI 生成提交信息。范围涵盖 Zed 托管模型、用户自备密钥和本地模型。 |
| Zed 账号与实时协作 | 移除登录、登出、凭证读取与续期、浏览器 OAuth、账号菜单、订阅与额度、组织入口，以及共同编辑、项目分享、联系人、频道、协作通知、通话和屏幕共享。 |
| 官方服务与上报 | 移除客户端对 Zed 官方服务的调用，包括扩展市场、官方远端二进制下载、产品遥测、崩溃采集与上报、应用内自动更新和更新助手。 |
| 编辑与本地开发 | 保留文件编辑、多窗口和会话恢复、查找导航、Markdown、语法高亮、普通代码片段、语言服务器补全与诊断、终端、任务、调试和 REPL。保留本地日志和错误反馈。 |
| Git | 保留克隆、暂存、提交、差异与历史、分支、标签、冲突处理及 fetch、pull、push 等操作。Git 凭证助手、SSH 密钥和 Git 托管方配置继续用于这些操作。GitHub HTTPS、SSH 和浏览器 PR 流程继续使用各自的认证。 |
| 扩展与远程开发 | 保留本地安装和加载的语言、主题、图标、代码片段与调试扩展。保留 SSH、WSL 和开发容器中的文件编辑、语言服务和终端。需要远端服务的连接使用自行部署的匹配版本。 |
| 构建与发布 | 保留本地编译、Windows 打包、手动发布和 Scoop 更新。Windows x64 是首轮可执行验收平台。 |

### 技术决策

- 产品入口与依赖图同步裁剪。移除待删功能的动作注册、默认键位、菜单、命令面板、设置 UI 与默认设置、深链接、初始化路径和运行时依赖。按保留目标的消费者判定共享 crate、协议类型和平台组件的去留。
- 分两批交付。先拆 AI，再拆账号、协作和官方服务。每批都通过保留功能的验证。仓库中仅服务于已移除功能的构建目标、依赖、资产、测试入口与部署配置随对应批次清理。
- 复用当前编辑器、Git、Workspace、Project 和扩展宿主。把保留功能所用的 HTTP、Git 凭证、SSH 传输和本地项目状态从账号与协作客户端的依赖中拆出。
- 升级沿用已有用户目录与编辑器配置。删除的设置项和动作可留在用户已有文件中，由加载逻辑兼容处理。保留磁盘上的历史数据与现有凭证存储以便回滚，精简版停止读取 Zed 账号凭证。
- 远程开发使用现有的远端服务部署目录和二进制发现机制。发布者构建并部署匹配目标平台与客户端版本的 `remote-server`。缺失或不匹配时，客户端指出预期路径和版本并结束连接。
- 保持 Windows 编辑器与 CLI 产物兼容现有 Scoop 替换流程，自动更新助手从构建、暂存、签名列表和安装器文件列表一起移除。Scoop 按已提供的本地产物手动更新。

## 设计视图

### 功能设计

启动时直接进入编辑器或恢复本地会话。编辑工具栏、标题栏、设置页、Git 面板和命令面板只显示保留功能。普通语言服务器补全与 Git 手写提交在原位置工作，原先对应 AI、登录、协作及应用内更新的可操作项随功能一起移除。

打开扩展界面时可以管理已安装扩展并从本地载入扩展。扩展宿主注册语言、主题和调试等保留能力。带有 AI 扩展声明的扩展仍可加载其保留能力，已移除的能力返回明确的不可用结果。扩展界面去除官方目录和联网更新入口。

通过 SSH 打开项目时，先使用既有 SSH 凭证和主机配置建立连接。远端二进制可执行且版本匹配时继续打开项目。检查失败时直接使用部署提示，下一次连接重新检查。Git 使用自身的远端认证流程，独立于旧的 Zed 登录流程。

### 技术设计

- `zed` 和 `workspace` 启动时只构造保留组件的状态。移除账号、协作和 AI 初始化。把普通下载、代理和进程凭证交给保留功能实际使用的客户端，清理 `UserStore`、协作连接和遥测身份的耦合。
- `editor`、`git_ui`、`project`、`title_bar` 和 `settings_ui` 裁掉 AI 与账号相关的分支，继续使用现有文本缓冲区、项目模型和 Git 仓库操作。扩展 API 的兼容边界只服务于仍受支持的扩展能力。
- `remote`、`remote_connection` 和 `remote_server` 复用现有的传输和 RPC。远端二进制准备流程消费已部署的匹配产物，移除指向 Zed 官方下载服务的分支。共享协议沿用保留功能仍使用的部分。[当前远端二进制准备流程](../../crates/remote/src/transport/ssh.rs)
- 清理 `Cargo.toml`、`Cargo.lock`、构建配置与发布流程。已移除功能独占的运行时实现从产物中去除。开发机仍可通过受控的 Cargo 和工具链依赖源构建。

## 验收

| 场景 | 可观察结果与验证 |
| --- | --- |
| 启动、编辑和开发 | 新配置与已有配置均可启动。验证文件编辑、Markdown 预览、多窗口与会话恢复、普通 LSP 补全与诊断，以及终端、任务与调试的主要入口。 |
| 功能移除 | 在菜单、命令面板、快捷键与设置中检查 AI、账号、协作和应用内更新入口均已清理。使用含旧设置与键位的用户目录启动，确认保留配置仍生效。 |
| 运行时网络与上报 | 在隔离的测试环境中阻断 Zed 官方服务并记录 DNS 和连接。验证启动、打开仓库、管理本地扩展和 SSH 的正反场景都不会尝试访问 Zed 官方接口。检查客户端及打包产物中已移除专属遥测、崩溃采集与上传组件，并验证本地日志可读。 |
| Git 与外部凭证 | 打开本地仓库，完成差异、暂存、手写提交、分支和冲突处理。使用受控 Git 远端验证 fetch、pull、push 和原有凭证流程，核对 GitHub 仓库链接与 PR 链接。 |
| 扩展与远程开发 | 在官方服务被阻断时加载本地的语言、主题及调试扩展，分别验证基本功能。验证 SSH、WSL 与开发容器的连接入口和编辑流程。部署匹配版本的远端服务完成 SSH 编辑，并验证缺失与不匹配时提示部署位置和版本。 |
| 代码与依赖 | 检查 Windows GUI、CLI 和远端服务的实际解析依赖图。确认 AI、账号、协作、遥测、崩溃和自动更新的专属可达依赖已清理，共享依赖有保留功能的调用方。 |
| Windows 产物与安装 | 构建 x64 GUI、CLI 和安装包，验证启动、版本和安装路径。检查包内无自动更新助手。使用隔离安装验证手动 Scoop 替换与回滚。 |
